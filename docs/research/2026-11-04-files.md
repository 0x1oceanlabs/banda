# Files: a finder and a previewer in Banda, and the module SDK it needs

- **Date:** 2026-11-04.
- **For:** Roma, before the `files` module's ADR (ADR 0034, step 5, and
  beyond it).
- **How:** read-only.
  - T3 Code's code was read in a shallow clone of github.com/pingdotgg/t3code
    at `a21d7887` (2026-11-04).
  - The Codex app, Claude Code Desktop, Zed, Conductor, Warp, Cursor,
    JetBrains Air, Antigravity and VS Code come from their docs and
    changelogs. GitHub issues and the press are marked as reports.
  - File managers and libraries come from their docs, code and licences.
  - Banda was read at `origin/main` `ddf0c68d`.
  - Nothing was run.
- **Status:** research only. Nothing here is an accepted Banda decision.
  The proposals in §6–§8 are ours, for Roma to decide.

**Verified** means read in code or in an official source. **Inferred** means
it is our reading, and it is marked so.

## Summary

1. **T3 Code's Files goes much further than ADR 0034 assumed.**
   - It has a lazy tree on `@pierre/trees`.
   - It has a viewer on `@pierre/diffs`, with its own WASM highlighter, not
     Shiki.
   - Its editor is `@pierre/diffs/edit`, and it saves 500 ms after typing.
   - It previews images, video, audio, PDF (pdf.js), CSV, notebooks, Office
     files, SQLite, archives, fonts and Mermaid.
   - Its bytes come through signed asset URLs.
2. **Its gaps are where Banda can be better.**
   - It does not watch the disk. The tree refreshes when an Agent's tool
     step ends, so the Person's own edits stay unseen until Refresh.
   - Saving has no conflict check: the last writer wins.
   - It has no create, rename, move or delete.
   - It does not link paths in plain prose.
3. **The other agent apps centre on the diff, not on files.**
   - Codex closed a request for a file tree as "not planned".
   - Claude Code Desktop has a file pane, but no tree in its docs.
   - Warp and Conductor added a small editor "for quick edits", and say they
     are not rebuilding an IDE.
   - What every one of them does well is make a path actionable. A click
     previews it; a modifier opens it in an editor; right-click offers
     attach, reveal and copy.
4. **The best file managers agree on a few things.**
   - The preview is the product (Quick Look's Space).
   - One selection is shown in several views: list, columns, gallery.
   - Work never blocks: listing streams, and operations are queued jobs
     with undo.
   - Everything is on the keyboard.
   - Delete goes to the Trash.
5. **Banda already holds most of the parts.**
   - `@pierre/trees` and `@pierre/diffs`, with the editor `@pierre/diffs/edit`
     installed but unused.
   - Shiki and Streamdown with Mermaid.
   - `app://files`, which already serves with signed tokens and HTTP Range,
     but only images, video and audio, and only for the agents module.
6. **What is missing is mostly SDK, not the Files UI.** A module has no
   byte channel of its own and no typed access to the desktop. Nothing
   watches files, and no helper keeps a path inside the Project.
   - Nothing lets a module register a previewer, claim links in replies,
     mark a Pane as one an Agent may open, or put a chip in the composer.
   - Registering a module still means editing about 12 hand-kept lists.
   - So Files is the right first app for "Banda app SDK". Each gap it hits
     becomes one SDK piece that every module after it gets.

## 1. T3 Code (verified, in code, at `a21d7887`)

### The tree

- **The component.** `apps/web/src/components/files/FileBrowserPanel.tsx`,
  inside `FilePreviewPanel.tsx`, on `@pierre/trees` `1.0.0-beta.6` (the same
  pin Banda has). Its settings: `density: "compact"`,
  `flattenEmptyDirectories`, `initialExpansion: "closed"`, search
  `hide-non-matches`, and no dragging inside the tree.
- **Lazy, one folder at a time.** `projects.listEntries {cwd, directoryPath}`
  (`apps/server/src/workspace/WorkspaceEntries.ts`) reads only that folder.
  It resolves symlinks in batches of 64 and refuses ones that leave the
  workspace or loop.
- **Ignored files are shown greyed, not hidden**, through
  `git check-ignore -z --stdin` in chunks of 1000. "Expand all" skips
  ignored folders.
- **A search index.** `@ff-labs/fff-node` builds a native index of at most
  25 000 entries; the first scan waits up to 15 s. Search is debounced
  120 ms, limited to 200 results, and merges the hits and their folders
  into the tree.
- **Reveal.** Opening a file from elsewhere loads its parents, expands
  them, selects the row and centres it (`loadFileAncestors.ts`).
- **Its menu** (native) has:
  - Open (the system app)
  - Reveal in Finder / Explorer / Files
  - Open with ▸ (each editor found on the machine)
  - Copy mention
  - Add to chat
- **Dragging rows into the composer** inserts mentions, and several rows
  can be dragged at once (`fileTreeDragMention.ts`).

### A file

- **Each file is its own tab** in the right panel, `file:<path>`, opened at
  a line that is centred and highlighted (`fileLineReveal.ts`).
- **Text** comes through `projects.readFile`:
  - At most 1 MB; past that the result is marked truncated.
  - A NUL byte means the file is binary.
  - Past 1 MB, `LargeTextViewer.tsx` reads it in a worker through an asset
    URL.
- **The view** is `@pierre/diffs`' `File` and `Virtualizer`, coloured by
  `@pierre/highlights` WASM lexers in a worker pool. The code calls them
  "10-40x faster than Shiki".
- **Lines.** Gutter clicks and drags pick lines, and a comment on them goes
  to the composer as review context.
- **Markdown** is rendered, with a source toggle. Ticking a task's box
  writes the file.
- **Previews.** Every format below except CSV and notebooks has its bytes
  served through `assets.createUrl`, as signed, expiring URLs, bounded while
  they stream.

| Kind | How |
|---|---|
| Image | `PreviewImage.tsx`, decoded in a worker; SVG and HEIC count as images |
| Video, audio | `MediaVideoPlayer`, `AudioPreview.tsx` |
| PDF | `pdfjs-dist` 6.4, or Chromium's viewer in a frame |
| HTML | a sandboxed iframe, or the integrated browser |
| docx, xlsx, pptx, odt, ods, epub, rtf | in a worker, on `@betteroffice/*` and `jszip` |
| Notebook | saved outputs only: "Code is never executed"; HTML outputs in frames made only while visible |
| CSV, TSV | a virtualised table with a source toggle |
| SQLite | `sql.js` |
| zip, tar, gz | listed |
| Font | `FontViewer.tsx` |
| Mermaid | `MermaidViewer.tsx` |

### Editing

- **The editor.** `@pierre/diffs/edit`'s `Editor` in an `EditProvider`. It
  is on only once the file is highlighted, and off for a truncated file,
  a file outside the workspace, or a connection without write scope.
- **Saving.** 500 ms after typing stops, and when the tab closes
  (`fileSaveCoordinator.ts`).
- **The write.** `projects.writeFile` creates folders, writes with
  `O_TRUNC | O_NOFOLLOW`, and refuses `.git`.
- **No conflict check.** It compares no mtime or hash; a newer copy from
  the disk replaces the draft.

### Watching

- **None.** Nothing in T3 watches the work tree.
- **A token instead.** `deriveWorkspaceMutationId` is made from the last
  completed command, file change, tool or subagent item and the last
  checkpoint; when it changes, the tree and the open file are read again.
  A turn's end also refreshes the search index.
- **The result:** the Person's own editor, or a `git checkout`, is not seen
  until Refresh.

### Paths in replies

- **What counts.** Markdown links, `file://` links, and inline code that
  looks like a path: it has a `/` or `:line`, no spaces, no hostname or
  version look, and an extension unless a line is given. Lines may be
  `:12`, `:12:3` or `#L12C3`. Prose is not scanned
  (`packages/shared/src/fileLinks.ts`).
- **The look.** A chip with the file's icon. A bare file name is resolved
  through search and checked to exist.
- **A click** opens the file at its line, but a PDF opens in the browser.
- **Mod-click** opens it in the preferred editor: the one used last, or the
  first found.
- **Right-click** offers Preview, Open in ‹editor›, Open in the browser,
  Reveal, Copy relative path (with its `:line`) and Copy full path.
- **The editors** are listed in `packages/contracts/src/editor.ts`: Cursor,
  VS Code (and Insiders, VSCodium), Zed, Trae, Kiro, Antigravity and the
  JetBrains family.
- **Launching** uses three styles: `--goto path:line:col`,
  `--line/--column`, or the path alone. Remote machines get
  `vscode-remote://` and `zed://ssh` URLs
  (`apps/server/src/process/externalLauncher.ts`).

### `@`, quick open and search

- `@` searches with fff (limit 80, debounced 120 ms) and inserts
  `[name](path)`. All the ranking is fff's.
- Mod+P (`ProjectFilePicker.tsx`) keeps the server's order.
- Mod+Shift+F searches contents: regex, case and whole word, 250 ms per
  call, at most 100 matches per file.

### Its RPC

| Method | In → out |
|---|---|
| `projects.listEntries` | `{cwd, directoryPath?}` → `{entries: {path, kind, ignored?}[], truncated}` |
| `projects.searchEntries` | `{cwd, query, limit≤200, kind?, imageOnly?}` → the same |
| `projects.searchContents` | `{cwd, query, caseSensitive, wholeWord, useRegex}` → matches with ranges |
| `projects.readFile` | `{cwd, relativePath, allowMissing?}` → `{contents, byteLength, truncated}` |
| `projects.writeFile` | `{cwd, relativePath, contents}` |
| `filesystem.getMetadata` | `{paths[]}` → `{kind, byteLength, mimeType}` or `null` per path |
| `shell.openInEditor` | `{cwd: path[:line:col], editor, reveal?}` |
| `assets.createUrl` | `{resource}` → `{relativeUrl, expiresAt, imageDimensions?}` |

Errors are tagged: `workspace_path_outside_root`,
`resolved_path_outside_root`, `path_not_file`, `binary_file`.

## 2. The other agent apps

- **The Codex app** (verified: learn.chatgpt.com/docs/code-review,
  …/artifacts-viewer)
  - Its file work is the review pane: Unstaged, Staged, Commit, Branch and
    Last turn, with stage, unstage and revert of a hunk or a file, and line
    comments.
  - A file name opens in the chosen editor, and Cmd-click opens it at its
    line.
  - Documents, sheets, slides, PDF and HTML preview beside the chat.
  - **Annotating a preview replaces editing it.** The Person points at a
    part and asks for a revision; only `.tex` is edited in place.
  - A request for a file tree was closed as "not planned"
    (openai/codex#19785, a report).
  - A "Toggle File Tree" menu item exists but shows nothing on Windows
    (#22388, a report).
- **Claude Code Desktop** (verified: code.claude.com/docs/en/desktop)
  - Its panes are chat, diff, browser, terminal, file, plan, tasks and
    subagent.
  - A path in chat opens the file pane. HTML, PDF and video open in the
    Browser pane.
  - **The file pane edits** in local sessions. It saves on its own or by
    Save. When the disk changed, it asks **Override** or **Discard**.
    Config files such as `.claude/settings.json` are view-only, and remote
    sessions are view-only.
  - **Right-click on any path**, in chat, the diff or the file, offers:
    - Attach as context
    - Open in ‹editor›
    - Show in Finder
    - Copy: the absolute path, the relative one, or the name
  - Its docs show no project tree; a request for one exists.
- **Zed** (verified)
  - Review Changes is one buffer of every edit, with keep or reject per
    hunk.
  - **Follow the agent:** the editor jumps to each file the agent reads or
    edits.
  - `@` takes files, folders, symbols, threads, diagnostics and diffs.
- **Conductor** (verified changelog)
  - A file explorer came in 0.16.
  - Manual Mode (0.37) added an editor "for quick edits, like `.env` files,
    json configs, or tailwind classes", and sends the rest to the AI.
- **Warp Code** (verified blog)
  - A "simple file tree for browsing, opening, and adding files as
    context".
  - Cmd-O opens and creates files.
  - Tabs, find and replace, vim keys.
  - "We aren't trying to rebuild an IDE."
- **VS Code agent edits** (verified)
  - Pending edits are kept or undone per hunk.
  - It warns that changes made by terminal commands may be missed. A Rust
    engine that watches the disk would not miss them (inferred).
- **JetBrains Air and Antigravity**: one Task Changes tab, and comments on
  artifacts that the agent takes in while it works.
- **Cursor 3's Agents Window**: forum users say it lacks file navigation (a
  report).

**What they chose.** None of them builds a full editor. The diff is their
main file view. A tree comes late or not at all, though people keep asking
for one, for quick open, and for dragging files out to other apps.

## 3. What the best file managers teach

Each line is what makes that one notable. GPL code (ranger, Nautilus and
Sushi, Dolphin, Zed) is a reference for its UX only; we copy none of it.

| App | What to take |
|---|---|
| Finder + Quick Look | Space previews and arrows keep moving under it. ⌥Space is fullscreen. Light acts inside the preview: rotate, trim, mark up. Column view and Gallery view. Tags and smart folders. ⇧⌘G goes to a folder |
| Path Finder | A drop stack: a shelf to gather files from many folders, then act on them |
| ForkLift, Marta, Commander One | A palette over every act. Copy and move run as queued jobs with progress and conflict questions, not blocking dialogs. Multi-rename with a live preview |
| Files (Windows, MIT) | Tabs, dual pane, columns, a preview pane, tags. Its code is a legal reference |
| Nautilus | Typing starts a search |
| Dolphin | A breadcrumb that becomes an editable path. Archives as folders |
| yazi (MIT) | Rust and async everywhere. Miller columns with a preview. Bulk rename in `$EDITOR`. Lua previewers (`peek`, `seek`) |
| broot (MIT) | The tree filtered as one types, not a flat list |
| Raycast, Alfred | One key, instant fuzzy results ranked by frecency, acts on the result (⌘K, ⌘Y for Quick Look), a buffer of several results |
| VS Code, Zed | Mod+P with name matches first and recent files boosted. Compact folder chains. Git status colours. Reveal the active file. Preview tabs that a single click replaces |

**Principles.**

1. **The preview is the product.** Space never takes the focus from the
   list.
2. **One selection, several views**: list, columns, gallery. The preview
   is a pane, not a mode.
3. **Nothing blocks.** Listing streams in, thumbnails load lazily and are
   cancelled off screen, and operations are jobs with progress and undo.
4. **Every act is on a key and in the palette**, and Mod+P opens a file.
5. **Search is fuzzy and ranked by frecency**, a name above a folder, with
   `.gitignore` respected and a toggle for it.
6. **Editing is chosen**: an explicit edit mode, a dirty mark, a save.
7. **A path can be typed**: the breadcrumb becomes a field.
8. **Bulk rename is text**: the names in an editor, then a diff before
   applying.
9. **Delete is the Trash**, and Mod+Z undoes it.

**Keys worth adopting.**

| Key | What |
|---|---|
| Space | Quick Look |
| ↵ / F2 | Rename |
| Mod+↓ / Mod+↑ | Open / Parent |
| Mod+1…4 | List, Grid, Columns, Gallery |
| Mod+P | Quick open |
| Mod+F, `/` | Filter |
| Mod+L | Path bar |
| Mod+⌫ | Trash |
| Mod+Z | Undo the last operation |
| Mod+Shift+. | Hidden files |
| ⌥Space | Fullscreen preview |
| Mod+I | Info |

A vim layer (hjkl, `gg`/`G`) can come later.

### The editor, measured (2026-11-05)

Roma asked for the two candidates side by side. Both were built with
esbuild, minified, with React 19. Each opened the same Rust text (Banda's
git engine, repeated to 2 000, 20 000 and 100 000 lines) in headless
Chromium 1200×900 with no GPU. The test jumped to the middle line and typed
30 keys. Two runs; the numbers below are both, where they differ.

- `@pierre/diffs/edit` 1.6.2 ran on the main thread, with no worker pool,
  in its default `highlights` and in `shiki`.
- CodeMirror 6 had `basicSetup`, `lang-rust` and One Dark.

| | Pierre 2k | CM 2k | Pierre 20k | CM 20k | Pierre 100k | CM 100k |
|---|---|---|---|---|---|---|
| First paint, ms | 16–20 | 47–58 | 20–25 | 39–53 | 26–39 | 58–66 |
| Key to paint, median ms | 6.3–6.5 | 17–19 | 6.3–7.1 | 9–11 | 1.6–7.7 | 23–24 |
| Key to paint, p95 ms | 11–15 | 20–22 | 12–18 (one run 70) | 34–39 | 18–130 | 26–38 |
| JS heap, MB | 10–22 | 9–12 | 84–117 | 19 | **160–557** | **43–51** |
| Typing landed | yes | yes | yes | yes | **once in two, per highlighter** | yes |

The key latency is measured to the next frame, so it rounds up to about a
frame. Read it as relative, not absolute.

**Size.**

- Pierre's editor is **169 KB** minified, on top of `@pierre/diffs` and
  Shiki, which Banda already ships for the Diff. It adds no dependency.
- CodeMirror with `basicSetup` and one language is about **600 KB** minified
  (about 250 KB gzipped). It is all new to Banda.

**What each has** (Pierre: read in `dist/editor/*.d.ts`; CodeMirror: its
docs).

| | `@pierre/diffs/edit` | CodeMirror 6 |
|---|---|---|
| Looks like the Diff and the viewer | the same component, the same colours, the same line selection and comments | its own theme to match |
| Editing in the diff itself | yes (`FileDiff` editor) | `@codemirror/merge` |
| Find, replace, regex | yes (`searchPanel`) | yes |
| Multiple cursors, move/copy line, comment, indent, brackets | yes | yes |
| Other people's carets (an Agent's cursor) | `setCarets`, `renderCaret` | possible, through decorations |
| Diagnostics | `setMarkers` | `@codemirror/lint` |
| Inline AI prediction | built in (`editPrediction`) | none, write it |
| Drafts kept across Panes | `editStateKey` with history | ours to keep |
| Vim | none | `@replit/codemirror-vim` |
| LSP | none | `@codemirror/lsp-client` |
| Folding, autocomplete | none | yes |
| Huge files | heavy: hundreds of MB at 100k lines, and typing did not always land | light, by viewport |
| Maturity | new; T3 Code ships it and patches `@pierre/diffs` | mature since 2022 |
| Licence | Apache-2.0 | MIT |

**Our reading** (inferred):

- **Pierre for the light editing Files needs.** It is faster on normal files
  and costs no new dependency. A file, its diff and its edit then look and
  behave as one thing. Agent carets and predictions come free.
- **It must stop at a size.** Past about 1 MB or 20 000 lines, Files shows a
  read-only large-file view, as T3 Code does past 1 MB.
- **Behind our own `Editor` interface**, so CodeMirror can take a file type
  or a mode (vim, LSP) later without the Panes knowing.

### Bytes to the window

- **Use what Banda has.** `app://files` (ADR 0037, decision 8;
  `modules/agents/desktop/src/files.ts`) is already right:
  - Tokens are HMAC-signed, last an hour, and are bound to the path,
    device and inode.
  - It reads with `O_NOFOLLOW`.
  - It answers HTTP Range.
  - It sends a `sandbox` CSP and `nosniff`.
- **What it lacks:**
  - It serves only images, video and audio.
  - It is the agents module's.
  - It accepts absolute paths outside the Project.
  - The page's `frame-src` excludes it.
- **The proposal:** move it into `desktop-kit` as a Project-scoped byte host
  any module can use. It would take every type, check that the path is
  inside the Project unless the Person picked it, and give the Pane a typed
  hook.
- **A second host for untrusted pages**, such as `app://preview`, for HTML,
  SVG and notebook outputs. Frames there get `sandbox="allow-scripts"`
  without `allow-same-origin`, and a strict CSP.
- **Small things keep riding RPC:** text up to a limit, thumbnails up to
  about 256 KB, hex ranges. Video, PDF and large images go through the
  host.

## 5. Banda today, against a files module

- **The rules.** ADR 0034 decision 5 gives `files.tree` and `files.file`,
  read-only at first, with "Copy path" and "Add to chat".
  - Decision 7 makes paths in replies links.
  - Decision 8 has everything open through `workspaces.open`, with
    `files.file` added to `AGENT_KINDS`.
  - Decision 9 sends picked lines as a comment.
  - Decision 11 says editing is not now.
- **`agents.files`.**
  - It runs `git ls-files`, or walks the folder up to 20 000 files.
  - It caches for 5 s.
  - It ranks by substring, not fuzzily.
  - It returns at most 50 paths, with no folders and no metadata.
  - `@` and the Banda menu use it, and the menu opens a file as a
    `file://` page in the browser Pane.
- **Links.** `markdown-link.tsx` handles http(s) only.
- **The desktop.** There is no bridge leaf to reveal a file, open it in an
  editor, or save a copy. `shell.showItemInFolder` serves browser downloads
  only.
- **Watching.** `git.watch` polls every 3 s, and nothing in the engine
  watches files.

## 6. Proposal: what Files is

Our reading of the Person's ask: "an elegant, functional app for files that
can grow deep" (Roma, 2026-11-04). Their sketch was a finder, previews of
media, PDF and code, some light editing, and the start of the Banda app
SDK.

**One line.** Banda's Finder and Quick Look, for any folder and first for a Project's. It is as
quiet as the Thread, it previews any file without leaving the list, and an
Agent's work shows on it as it happens.

**The Panes.**

| Kind | What |
|---|---|
| `files.tree` | The browser. A lazy tree: ignored files greyed, git status and "changed this turn" as decorations, search that filters the tree (broot), reveal. Later Columns and Gallery over the same selection (decision 9) |
| `files.file` | One file, drawn by the previewer that claims its type, opened at a line. Read-only first, light editing later |
| Quick Look | Space on a row floats a preview over the desk (ADR 0023's floating tiles), arrows move under it, Space closes it. It is `files.file` in quick mode, not a third viewer |

**Where Banda can be better than T3 Code, deliberately.**

1. **It watches the disk.** The engine runs `notify` on the folders the
   tree shows (non-recursively on Linux) and streams the changes.
   - The Person's own editor and a `git checkout` show at once.
   - The same service lets git stop polling every 3 s.
2. **It saves with a base.** A write carries the hash it was read at.
   - When the disk moved, the Pane asks **Keep mine / Take theirs**, as
     Claude Desktop's Override / Discard does.
   - An Agent's write mid-edit is never lost silently.
3. **It follows the Agent** (Zed). The tree marks the files the running turn
   reads and writes, and with "Follow" on, `files.file` moves to the file
   being edited.
4. **It does operations, safely**: new file and folder, rename, move,
   duplicate, Trash with undo, and bulk rename as text with a diff. T3 Code
   has none.
5. **It links paths anywhere in a reply**, in prose too, with a check that
   the file exists, so a false link never shows.
6. **Its previewers are a public interface** (§7), so a module from
   elsewhere can add a format.

## 7. Proposal: the SDK pieces Files needs

Each is built once for Files and is then any module's. ADR 0005,
decision 12, already asks that Banda's own modules use only what a module
from elsewhere would get.

1. **A byte host for modules** (§4): Project-scoped, signed, ranged, with a
   typed `useFileUrl(space, path)` in `@banda/ui`, and a sandbox host for
   untrusted pages.
2. **A typed desktop bridge for Panes**: `reveal`, `openIn(editor, path,
   line)` (with the editors found on the machine), `openWithSystem`,
   `saveAs`, drag out to other apps. Panes stop casting `window.banda`.
3. **A watch service in the kernel**: `ModuleSpace::watch(paths)` giving
   debounced, coalesced changes, with a rescan on overflow. Files and git
   share it.
4. **Reachable paths.** A `FilePath` type that only a resolved path the
   caller may reach can be: inside the Project's folder for an Agent, or
   any folder the Person opened (Roma: Files reaches any folder). It
   refuses `..` and escaping symlinks. Every method that takes a path takes
   it; `agents.media` would take it too.
5. **Previewers.** `definePreviewer` in `@banda/ui/module`, declared in
   `defineModule({ previewers })`:

   ```ts
   definePreviewer({
     id: "files.pdf",
     match: { ext: ["pdf"], mime: ["application/pdf"] },
     priority: 0,                 // the Person can choose another, "Open with…"
     can: { quick: true, edit: false, find: true },
     load: () => import("./PdfView"),   // lazy
   })
   // the view gets: { file: {path, name, mime, size, mtime, url(range?)},
   //   read(range), mode: "quick" | "pane", line?, theme, signal,
   //   dirty?(yes), save?(bytes, base) }
   ```

   - The previewer is picked by extension, then MIME, then magic bytes,
     then priority, and the Person can override it.
   - A view is updated, not remounted, as the selection moves within one
     type: that is what keeps Quick Look instant.
   - A module from elsewhere would run its previewer in a sandboxed frame
     (inferred; not for now).
6. **Link claims.** A module claims a pattern in replies (`path:line`,
   `#L12`) and what a click, a modifier-click and the menu do. Files claims
   paths; `pulls` will claim PR URLs (ADR 0034 decision 7).
7. **Panes an Agent may open**, declared on the Pane (`agent: true`), not
   listed in `workspaces`' `AGENT_KINDS`.
8. **Into the composer.** `WindowApi.attach(chip)` puts an `@` chip, lines
   or a comment into the focused Thread's composer. "Add to chat", dragging
   and decision 9's comments all use it.
9. **UI blocks** in `app/ui`: `CodeFile` (over Pierre's `File`), `Editor`
   (behind the interface of §4), `FileIcon` (Pierre's icon set, as T3 uses
   it), `VirtualList`.
10. **One place to register a module.** A `banda new module <id>`, or a
    build step, writes the 12 hand-kept lists. This one is not needed for
    Files, but it is what makes an SDK.

Each step is a PR or two and ships something the Person can use.

1. **F1, the tree and a file** (ADR 0034, step 5).

## 10. Risks

- **Licences.**
  - Copy no code from GPL projects: ranger, Nautilus, Dolphin, Zed.
  - ffmpeg only as an LGPL build beside Banda.
  - libheif is LGPL.
  - `nucleo` is MPL: change none of its files, or keep them MPL.
- **Linux watching.** inotify has a watch limit and drops events. Watch
  only what is shown, rescan on overflow, and say how to raise
  `max_user_watches`.
- **Codecs.** HEVC and HEIC are uneven, and MKV is partly supported. "Open
  in ‹app›" must be there from the first day.
- **Betas.** `@pierre/trees` is a beta, and T3 patches `@pierre/diffs`. Pin
  them and keep them behind our components.
- **Huge files.** Multi-GB logs and CSVs need reads by range, a read-only
  view past a size, and work that can be cancelled.
- **Safety.** A path in a URL, an inlined SVG or a same-origin preview frame
  would let a file read the disk. The guards are tokens, `ProjectPath`, the
  sandbox host and the CSP.
