# Banda on Windows: what the code needs and what Windows offers

Research for [ADR 0090](../adr/0090-banda-runs-on-windows.md), 2026-11-07.

Five readers went through the repository at `089cd164` (main), each for
one part: the Rust workspace, the window and the page, the Harnesses, the
release, and the engine as a service with its owner channel and fence. A
critic then read the first draft of the ADR against the code and the
dependencies' sources. Every `path:line` is at `089cd164`; to open one:
`https://github.com/0x1oceanlabs/banda/blob/089cd164/<path>#L<line>`.

**Limits.**

- Nothing was built for Windows. No Windows Rust target was installed,
  and no Windows machine was used. What the code does on Windows is read
  from the code and from the dependencies' sources in `~/.cargo/registry`
  and `node_modules`.
- Facts about Windows, Claude Code, Codex, Electron, signing and prices
  come from the vendors' pages, read on 2026-11-07. Where a reader could
  not check something, it says so; those are laptop tests.
- The probe for the laptop is
  [`2026-11-07-windows-probe.ps1`](2026-11-07-windows-probe.ps1). It was
  not run: PowerShell is not installed here.

**What the critique corrected.** The readers' notes below are kept as
written, but for these points, where the ADR follows the critique (§6):

- **ConPTY through `portable-pty`** (§1.3, §3.3). portable-pty 0.9.0
  starts the program with fixed flags, so it cannot be born in its Job
  Object; always asks for `PSEUDOCONSOLE_INHERIT_CURSOR`, which hangs a
  terminal no Pane answers; and loads a bare `conpty.dll` by name before
  kernel32's. The ADR starts the ConPTY with Banda's own code.
- **"Children get the same flags" as the engine** (§1.2, §5). A child
  started with `CREATE_NO_WINDOW` gets a hidden console of its own, which
  a Ctrl+Break from the engine cannot reach. Only the engine's own start
  is hidden; its programs inherit its console. The ADR sends no
  Ctrl+Break in v1.
- **`CREATE_BREAKAWAY_FROM_JOB` for `banda start`** (§1.5, §5.2). It fails
  inside a Job Object that does not allow breaking away, and Banda's must
  not. A client inside Banda's Job Objects never starts an engine.
- **The installer and the engine** (§4.2). electron-builder's PowerShell
  check matches `$INSTDIR` with no `\` after it, so installing Banda also
  stops Banda Dev; its fallback kills by program name.
- **Do Not Disturb** (§2). `SHQueryUserNotificationState` does not report
  Focus Assist or Do Not Disturb.
- **A build id written by `build.rs`** (§1.11) is not unique. The ADR
  reads the PE's CodeView GUID.
- **Signing Dev without its DLLs** (§4.3). Smart App Control checks DLLs
  too, so such a Dev would not start where it is on. Signing everything
  costs about $40 a month at today's pace.
- **claude-code#46740** (§5.5), the request for a native Windows sandbox,
  was closed as not planned, not left open.

## 1. The engine: the Rust side

### 1.0 The short answer

1. **The workspace does not compile for Windows today.** The first error
   is in the kernel: it depends on `pty-process`, which uses
   `std::os::fd` and `std::os::unix` with no `cfg(unix)` gate
   (`kernel/Cargo.toml`, `kernel/src/environment.rs:65`). After that come
   12 more call sites in 8 crates, listed in §1.1.
2. **Even "Windows as a client only" needs this fixed.** ADR 0081 lets a
   Windows machine be a client of a Linux host, and then the Windows
   engine is not needed. But the window still runs `banda look --follow`,
   `banda look themes` and `banda settings …`
   (`client/desktop/src/look.ts:38`, `settings.ts:34`). The
   `banda-settings` crate depends on agents, files, harnesses and
   terminal, which pull in the kernel, which pulls in `pty-process`. So
   step 0 is the same either way: the whole workspace compiles on
   Windows.
3. **The engine crate is mostly ready.** It already has `cfg(not(unix))`
   stand-ins (`engine/src/serve.rs:83-86`, `:176-179`, `:225-238`;
   `control.rs:372-392`; `main.rs:761-764`). The kernel, terminal,
   harnesses, look and files crates are not.
4. **What has no simple Windows equivalent:** process groups and signals;
   the PTY; `/proc`; systemd; the fence (namespaces and Landlock).
5. **What already works:**
   - The engine API is TCP on `127.0.0.1` with an owner secret
     (`engine/src/places.rs:24`, `serve.rs:189-201`). Binding loopback
     raises no firewall prompt.
   - The `engine.lock` and project locks use `std` `File::try_lock`,
     which is `LockFileEx` on Windows. `engine.lock` is only locked,
     never read (`engine/src/serve.rs:42-57`), so Windows' mandatory
     locking does no harm.
   - SQLite, `reqwest`/rustls, `notify`, `trash` and `sysinfo` all
     support Windows.
6. **A rule that shapes the design.** `unsafe_code = "forbid"` is set for
   the whole workspace (`Cargo.toml:106`), and all 20 crates inherit it.
   Job Objects, ConPTY, `GenerateConsoleCtrlEvent` and access rules on
   named pipes all need Win32 calls. So the choice is either crates with a
   safe API (`process-wrap`, `portable-pty`, `interprocess`, `listeners`,
   `sysinfo`, `windows-registry`), or one audited `platform/windows` crate
   that is exempt from the lint.

### 1.2 Process groups, signals and stopping

**Today.** Every program Banda starts leads its own process group:
`local.rs:32` sets the group; a stop sends `TERM`, then `KILL` to the
whole group (`git/run.rs:527-551`, `acp/pipes.rs:138-153`,
`terminal.rs:186-205`); the engine itself stops on `SIGTERM`
(`serve.rs:84`, `control.rs:377-387`, `service.rs:317`).

**On Windows there are no process groups and no signals.**

| Unix | Windows |
|---|---|
| A group of its own, so a kill reaches the grandchildren | A **Job Object** per program, with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`. Dropping the handle kills the tree. [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) |
| `SIGKILL` to the group | `TerminateJobObject` |
| `SIGTERM` to the group | `GenerateConsoleCtrlEvent(CTRL_BREAK_EVENT, pid)` to a child started with `CREATE_NEW_PROCESS_GROUP` that shares the engine's console. [GenerateConsoleCtrlEvent](https://learn.microsoft.com/en-us/windows/console/generateconsolectrlevent), [creation flags](https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags) |
| `SIGHUP` to a terminal's group | `ClosePseudoConsole`, which sends `CTRL_CLOSE_EVENT` to every process attached to it |
| `SIGTERM` to the engine (`banda stop`) | An owner API call over the WebSocket the CLI already opens (`control.rs:223`). A detached engine gets no console signals |

- **A Job Object is needed, not just nice to have.** On Windows
  `kill_on_drop` kills only the direct child. Harness CLIs from npm are
  `.cmd` wrappers (`claude.cmd`, `npx.cmd`), and each adds a `cmd.exe`
  layer. Killing that `cmd.exe` leaves `node.exe` running.
- **There is a race.** The Job Object must be in place before the child
  starts children of its own. `ProcessGroup::of(&child)` runs after spawn
  (`environment.rs:77`), which is too late on Windows.
  [`process-wrap`](https://docs.rs/process-wrap) (watchexec, v10) starts
  the process with `CREATE_SUSPENDED` and resumes it once the Job Object
  is set. It also has `ProcessGroup`/`ProcessSession` for Unix,
  `KillOnDrop` and `CreationFlags`, all on tokio. Its `JobObject` sets
  `KILL_ON_JOB_CLOSE` only (`src/windows.rs`, 10.0.1), so no breaking
  away.
- **Console windows.** An engine started with no console makes each
  console child (`git`, `node`, `gh`) open a new visible console window.
  Bookkeeping spawns outside the port: `platform/git-cli/src/lib.rs:244`,
  `kernel/src/foreign.rs:90`, `apps/pulls/engine/src/github.rs:49`,
  `platform/problems/engine/src/issue.rs:84`,
  `platform/harnesses/engine/src/carried.rs:181`. An engine started with
  `CREATE_NO_WINDOW` has a hidden console that its children inherit.
- **git and its lock.** `run.rs` sends `SIGTERM` so that git removes
  `.git/index.lock`. Whether Git for Windows removes it on `CTRL_BREAK`
  is untested. If it does not, Banda removes a stale `index.lock` itself
  after it has killed git.
- **The port's type.** ADR 0084's plan, step 1, already says: "Before
  step 3, the port hands back a handle that stops what it started." That
  handle can be the one type: ask to stop, kill, and the leader. Then the
  git, terminal and pipes code no longer touches `rustix` at all.

Size: **M.** The type change touches the kernel, environments, terminal,
harnesses/acp and git.

### 1.3 Terminals: pty-process becomes ConPTY

**Today:** `terminal.rs:61` calls `pty_process::open()`; the program
starts as session leader on the PTY (`local.rs:37`); `front.rs:42` asks
`tcgetpgrp` for the group in front, then reads `/proc/<pid>/cmdline` and
`cwd` (`front.rs:76-93`); `shell()` uses `$SHELL`, else `/bin/sh`
(`terminal.rs:300-305`).

**On Windows:**

- **The PTY is ConPTY** (`CreatePseudoConsole`, Windows 10 1809, build
  17763 or later).
  [Creating a pseudoconsole session](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session).
- **Options:** [`portable-pty`](https://docs.rs/portable-pty) (WezTerm;
  Unix PTY and ConPTY), whose reader and writer block and whose `Child`
  is its own; the `conpty` crate; or own code on `windows-sys`, which
  needs the unsafe exception. (See the corrections above: the ADR takes
  the third.)
- **Resize** is `ResizePseudoConsole`. **Close** is `ClosePseudoConsole`,
  which plays the part of the hangup, then `TerminateJobObject` after the
  grace period.
- **Exit:** there is no `status.signal()` (`terminal.rs:153`). A program
  stopped by Ctrl+C exits with an NTSTATUS code such as `0xC000013A`.
- **What runs in front:** there is no foreground process group. Either
  walk the shell's process tree (the newest descendant, with `sysinfo`'s
  `parent()`, `cmd()` and `cwd()`, which work on Windows), or read the
  shell's own escape sequences (OSC 133/633 as VS Code does, OSC 7 or
  OSC 9;9 for the folder). `front.rs:166-168` splits on `/` only and
  keeps `.exe`. `front.rs:174` writes `~/`.
- **The default shell:** `pwsh.exe` when it is on PATH, else
  `powershell.exe`, else `%ComSpec%`.
- **Optional:** ship a newer `conpty.dll` and `OpenConsole.exe`, as VS
  Code and WezTerm do. The conhost built into Windows 10 re-draws the
  screen and drops some escape sequences.

Size: **L**, a week or more, with front-program detection and tests.

### 1.4 Servers started in Banda (ADR 0044)

**Today, on Linux:** `/proc/net/tcp` and `tcp6` give listening sockets by
inode (`servers.rs:405-441`). The engine matches them to processes
through `/proc/*/fd` (`:389-401`), reads the Project from
`/proc/*/environ` (`:353`), and parent and group from `/proc/*/stat`
(`:445-470`). On macOS it uses `lsof`, `ps` and `sysinfo` (`:473-`). On
Windows the `cfg(not(target_os = "macos"))` branch would compile once the
imports at `:11` are fixed, but would find nothing.

**On Windows:**

- **Listening ports and their PIDs:**
  `GetExtendedTcpTable(TCP_TABLE_OWNER_PID_LISTENER)`, for IPv4 and IPv6
  ([docs](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getextendedtcptable)).
  [`listeners`](https://docs.rs/listeners) 0.6 wraps this for Windows,
  Linux and macOS, and could replace both the `/proc` code and the `lsof`
  parsing. Do not parse `netstat -ano`: its `LISTENING` column is
  translated on non-English Windows.
- **A process's environment, command line and parent:** `sysinfo`, which
  reads the process's PEB for processes of the same user. Today it is a
  macOS-only dependency (`apps/terminal/engine/Cargo.toml`).
- **"A Harness's own listener"** (`harness_s`, `servers.rs:185-210`)
  relies on process groups. It must be redone with parent chains.
- **Stopping a server** (`servers.rs:275-283`): kill the process tree. A
  graceful Ctrl+C to a process on another console needs a helper
  (`FreeConsole`, `AttachConsole`, `GenerateConsoleCtrlEvent`). Without
  it, the stop is a hard kill, which is what `taskkill /T /F` gives
  Windows users anyway.

Size: **M.**

### 1.5 The engine as the machine's service (ADR 0086)

**Today:** a systemd user unit through `systemd-run --user`
(`service.rs:285-350`); `own_unit` reads `/proc/self/cgroup`
(`:264-268`); `way()` returns `Child(NotYet)` on every system but Linux
(`:227-229`). So on Windows the engine is already the window's child, as
on macOS, and `parent::on_gone`, which waits for stdin to close
(`engine/src/parent.rs`), works on Windows. That is enough for a first
Windows build.

| Option | Verdict |
|---|---|
| A detached process that any client starts: `banda start` spawns `banda serve` with `CREATE_NO_WINDOW \| CREATE_NEW_PROCESS_GROUP \| CREATE_BREAKAWAY_FROM_JOB`. Clients restart it after a crash | Recommended. Windows ends it at logoff, which matches "stops when the Person logs out" |
| A per-user Scheduled Task, started on demand (`schtasks /run`), set to restart on failure | A named "unit" to ask about. `schtasks /end` is a hard kill, so a stop must still go through the API. [schtasks](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/schtasks) |
| A Windows Service | No. It runs in session 0 as another account, without the Person's environment or files |

- `banda stop` uses the owner API instead of `terminate()`
  (`control.rs:377-392`).
- `alive()` (`control.rs:349-375`) returns `false` off Unix, so
  `banda stop` would think the engine is gone at once.
- **Logoff and shutdown look like a crash.** A console program that loads
  `user32.dll` gets no `CTRL_LOGOFF_EVENT` or `CTRL_SHUTDOWN_EVENT`;
  Microsoft says to make a hidden window and handle `WM_QUERYENDSESSION`
  and `WM_ENDSESSION`
  ([SetConsoleCtrlHandler](https://learn.microsoft.com/en-us/windows/console/setconsolectrlhandler)).
  Without it, every logoff shows up as a crash Problem
  (`serve.rs:60-66`).
- **The engine's own copy** (ADR 0086, decision 2): a running `banda.exe`
  cannot be deleted or overwritten, only renamed. Removing old versions
  must skip any that are still running.

Size: **M.**

### 1.7 Private files

- The call sites: `engine/src/places.rs:270-283` (`engine.json` with the
  owner secret, and `owner.json`); `kernel/src/passes.rs:153`;
  `platform/problems/engine/src/panics.rs:68`;
  `apps/files/engine/src/thumb.rs:439`; `write.rs:119-123`. All are
  `cfg(unix)`. On Windows a file takes the access list of its folder.
- **Under `%LOCALAPPDATA%` this is fine:** its default list is the user,
  SYSTEM and Administrators.
- **Elsewhere it is not.** If `BANDA_STATE` points under `C:\`, the
  inherited list gives the Users group read access.
- **Atomic replace by rename** (`places.rs:282`, settings writes,
  `tempfile` `persist`): Defender or an indexer can hold a file for a
  moment, which gives `ERROR_ACCESS_DENIED` or `ERROR_SHARING_VIOLATION`.
  Retry a few times on Windows.

### 1.8 Places and paths

- **XDG folders** (`engine/src/places.rs:120-150`). With `dirs` 6 on
  Windows, `state_dir()` is `None`, so state falls back to
  `data_local_dir`. Data and config are both `%APPDATA%\banda` (Roaming),
  state and cache both `%LOCALAPPDATA%\banda`. The SQLite stores sit in
  Roaming, which a company's roaming profile syncs.
- **`canonicalize()` returns `\\?\C:\…`** (31 calls in 18 files outside
  tests; `kernel/src/kernel.rs:1465`, `reach.rs:33-38`). The prefix shows
  up in the UI and in `engine.json`; `cmd.exe` refuses it as a working
  folder; and a relative path with `/` joined onto it is broken. Use
  [`dunce::canonicalize`](https://docs.rs/dunce).
- **Case:** NTFS ignores case. `reach.rs:38` (`starts_with`) and
  comparisons of Project folders should ignore case on Windows.
- **Assumptions about `/`:** `platform/harnesses/engine/src/cli.rs:93`
  (`C:\…\claude.exe` has no `/`, so it is looked up on PATH as a bare
  name); `front.rs:167`; `kernel/src/kernel.rs:1165` and `:1497`;
  `apps/files/engine/src/settings.rs:116`; `find.rs:99`;
  `apps/pulls/engine/src/shell.rs:67` and `:168`.
- **Names Windows refuses:** `apps/files/engine/src/ops.rs:29-41` already
  refuses `\`. Add `<>:"|?*`, `CON`, `NUL`, `COM1`…`LPT9`, and a trailing
  dot or space.
  [Naming files](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file).
- **git's hooks folder:** `platform/git-cli/src/lib.rs:151` sets
  `core.hooksPath=/dev/null`. Git for Windows reads that as `\dev\null`
  on the current drive, which an Agent could create.
- **Long paths:** Rust `std` handles them. git needs `core.longpaths=true`
  for deep `node_modules`.

### 1.9 PATH

- On Linux the service gets PATH from `$SHELL -ilc`
  (`service.rs:410-445`). That code runs only for systemd.
- On Windows a process gets its environment from the registry at logon
  (`HKCU\Environment` plus
  `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment`). A
  long-lived engine keeps a stale PATH after the Person installs `claude`
  or `node`. [`windows-registry`](https://docs.rs/windows-registry) is
  already in `Cargo.lock`, through `reqwest`'s `system-proxy`.
- **Variable names ignore case.** Banda's own `BTreeMap`s (`Program.env`,
  `harness.env`, `apps/agents/engine/src/lib.rs:153-169`) can hold both
  `PATH` and `Path`.
- **`.cmd` wrappers:** `Command::new("npx")` does not find `npx.cmd`
  (`platform/harnesses/engine/src/list.rs:768`); `located()` and
  `runnable()` need `PATHEXT` (`cli.rs:92-104`); `node_on` must look for
  `node.exe` (`carried.rs:161-163`); `packed()` knows the Linux and macOS
  layouts only (`carried.rs:134-150`). Rust quotes arguments for `.cmd`
  safely since 1.77.2
  ([CVE-2024-24576](https://blog.rust-lang.org/2024/04/09/cve-2024-24576.html)).

### 1.10 Links, renames and open files

- **Making a link** (`apps/files/engine/src/ops.rs:485-493`) needs
  Developer Mode or admin rights, else `ERROR_PRIVILEGE_NOT_HELD` (1314).
- **Moving a Project folder** (`kernel/src/project.rs:452`) fails while
  any process has a folder or file open under it: a Harness or shell
  working there, or Banda's own `notify` watcher.
- **Deleting or renaming a file that is open** fails on Windows.
- **`notify`** uses `ReadDirectoryChangesW`, unreliable on network drives
  and on `\\wsl$\`.

### 1.11 Smaller items

- **Build id** (`engine/src/build_id.rs:24-30`): it reads ELF and Mach-O
  only, and `engine/build.rs:26-27` adds `--build-id` only on Linux. A PE
  carries the CodeView `RSDS` GUID and age when it is linked with
  `/DEBUG`, which `debug = "line-tables-only"` (`Cargo.toml:87-88`)
  already asks for.
- **The look crate's Linux readers:** `fc-match` (`fonts.rs:131`),
  `gsettings` and Omarchy (`wallpaper.rs`, `theme.rs:83-122`) fail

## 2. The window, the page and the trial scripts

### 2.1 Summary

The page and the terminal renderer are close to ready. Ghostty is
WebAssembly, and T3's adapter already knows Windows paths and AltGr. The
work is in the Electron main process and the scripts. Most serious first:

1. **Ctrl-clicking a program runs it.** "A click never runs a program"
   depends on the Unix exec bit (`client/desktop/src/outside.ts:39-45`).
2. **UNC paths reach the network.** `outside.ts` and `editors.ts` stat
   any absolute path, including `\\host\share\...`, which starts an SMB
   connection and sends the Person's NTLM hash.
   `desktop-kit/src/files.ts:102-103` already refuses `\\`.
3. **The window and the engine use different folders**
   (`client/desktop/src/channel.ts:62-78` against
   `engine/src/places.rs:121-150`).
4. **The window cannot start or reach a Windows engine:** no `.exe`, the
   socket is a Unix path, children are stopped with SIGTERM (a plain kill
   on Windows), and `extraResources` packs `target/release/banda`.
5. **No updater and no installer.**
6. **No AppUserModelID**, so Windows notifications will not show.
7. **Two bars.** `OWN_FRAME` is macOS-only.
8. **Keys.** Alt+Space clashes with the window menu and PowerToys Run;
   Mod+Shift with Alt+Shift's layout switch; Ctrl+Alt is AltGr on many
   layouts; Super is mostly taken by Windows.
9. **Glass.** ADR 0030 and the code say acrylic, ADR 0080 says Mica. The
   code sets a transparent background without `transparent: true`, and
   Electron says the alpha is ignored then.

### 2.3 The terminal renderer

- It is libghostty-vt compiled to WebAssembly
  (`src/t3/vendor/ghostty-vt.wasm`), drawn on a 2D canvas. Nothing native
  is loaded, and the CSP allows `'wasm-unsafe-eval'`
  (`client/desktop/src/main.ts:123`).
- T3's adapter handles drive-letter, UNC and PowerShell-prompt paths
  (`src/t3/lib/terminal-links.ts:31-37`), AltGr text
  (`src/t3/surface.ts:392-393`), and Windows middle-click autoscroll
  (`surface.ts:372`).
- ConPTY asks the terminal for win32-input-mode (`?9001`) when it is
  created with that flag, and for focus events (`?1004`). ghostty-vt
  ignores 9001 and falls back to plain VT input.
- PowerShell sends no OSC 7, so "program + folder" Pane labels (#272) need
  the engine's own source on Windows.
- **Text quality.** The canvas has alpha, so Chromium cannot use ClearType
  there and text is greyscale. Try it at 100/125/150 %.

### 2.7 Keys (the default mod is Alt, `sdk/contract/src/look.ts:141`)

- **Alt+Space is `menu.open`** (`client/web/src/shell/actions.ts:808-811`).

- **Mod+Shift keys** (`actions.ts:440-1036`): with two or more layouts,

- **Ctrl+Alt as the mod** (`client/web/src/settings/Mod.tsx:31-34`): AltGr

### 2.8 The engine as the window's child

- **No `.exe`:** `target/debug/banda` (`main.ts:153`),
  `join(resources, "banda")` (`program.ts:107`), the copy
  (`program.ts:194`, `:264`), `extraResources`
  (`client/desktop/electron-builder.config.mjs:32`).
- **The copy:** `mode: 0o755` means nothing on Windows; `putInPlace`
  renames a folder that may hold a running exe (`program.ts:279-282`);
  nothing is pruned (`program.ts:327-352`).
- **The Electron that runs the adapters:** `electron: process.execPath`
  (`main.ts:158`) and `BANDA_NODE: process.execPath` (`main.ts:165`). An
  NSIS update cannot replace `Banda.exe` while they run.
- **The socket:** `openDoor()` listens on `state/window.sock`
  (`client/desktop/src/door.ts:21-35`, `engine/src/places.rs:210`). Node on
  Windows listens only on `\\.\pipe\…`
  ([Node: IPC paths](https://nodejs.org/api/net.html#identifying-paths-for-ipc-connections)),
  so the listen fails and is only logged (`door.ts:30`).
- **Stop:** `child.ts:42-43` sends SIGTERM, then SIGKILL after 5 s. On
  Windows both are TerminateProcess. Closing stdin (`child.ts:26-28`)
  works.
- **No tray.** `window-all-closed` quits (`main.ts:836`).

### 2.9 Opening files outside Banda (security)

- **`runs()` (`outside.ts:39-45`)** uses `mode & 0o111`. Node reports
  Windows files as `0o100666` or `0o100444`. So `openFile()` calls
  `shell.openPath()` on every path (`outside.ts:22-23`), and ShellExecute
  runs `.exe`, `.bat`, `.cmd`, `.ps1`, `.lnk`, `.url`, `.scr`, `.msi`,
  `.hta`, `.vbs`, `.js`, `.wsf`, `.cpl`, `.reg`, `.appref-ms`… Files an
  Agent wrote have no Mark of the Web, so there is no SmartScreen prompt.
  The test (`outside.test.ts:7-13`) has Unix cases only.
- **UNC paths:** `openFile`, `exists` and `showFile` (`outside.ts:18-36`,
  called through `files.outside`, `files.exists`, `files.show` at
  `main.ts:423-425`) and `Editors.open` (`editors.ts:302`) take any
  `isAbsolute` path. The terminal detects UNC paths as links
  (`terminal-links.ts:35`, `:37`), and `files.exists` runs on them.
- **`.toml` files** (`main.ts:381`, `client/desktop/src/settings.ts:92`):
  stock Windows has no app for `.toml`.

### 2.10 Editors

The commands are `code.cmd`, `cursor.cmd`, `idea64.exe` and Toolbox
`*.cmd`. The search joins the bare name (`editors.ts:196-199`). A `.cmd`
spawned with `shell: false` throws `EINVAL` since Node's April 2024 fix
([CVE-2024-27980](https://nodejs.org/en/blog/vulnerability/april-2024-security-releases-2)).

  [claude-agent-acp#1041](https://github.com/agentclientprotocol/claude-agent-acp/issues/1041),
  [codex-acp#431](https://github.com/agentclientprotocol/codex-acp/issues/431).

**PTY and process trees.** [node-pty](https://github.com/microsoft/node-pty)
uses ConPTY on 1809+. Rust: [portable-pty](https://crates.io/crates/portable-pty)
0.9.0 (sync API); alacritty_terminal's `tty::windows`;
[conpty-oxide](https://crates.io/crates/conpty-oxide) 0.1.2;
[rust-pty](https://lib.rs/crates/rust-pty) (unstable).

**Electron.** Windows 10 and up, x64 and arm64
([README](https://github.com/electron/electron#platform-support)). Banda
pins Electron 45.1.0. Windows 10's consumer extended updates ended on
2026-10-13.

**WSL2.**

- `wsl --install` needs Windows 10 2004 (19041)+; the manual route
  1903 (18362)+ ([install](https://learn.microsoft.com/en-us/windows/wsl/install)).
  It needs virtualization on in firmware.
- systemd works with `[boot] systemd=true`
  ([wsl-config](https://learn.microsoft.com/en-us/windows/wsl/wsl-config)).
- A distro shuts down after `instanceIdleTimeout` (15 s), the VM after
  `vmIdleTimeout` (60 s).
- `[automount]` and `[interop]` are on by default, so WSL is not a wall.
- In NAT mode Windows reaches WSL's localhost; mirrored mode (Windows 11
  22H2+) works both ways
  ([networking](https://learn.microsoft.com/en-us/windows/wsl/networking)).
- AF_UNIX between Windows and WSL2 does not work
  ([microsoft/WSL#5961](https://github.com/microsoft/WSL/issues/5961)).
- Variables cross `wsl.exe` only through `WSLENV`.

### 3.4 Native, WSL2, or both

- **A. Native.** What a Windows user expects; both vendors default to it.
  Needs all of §3.2, ConPTY, Job Objects, `PATHEXT` and registry PATH,
  the Node choice. No fence, so Supervised by default.
- **B. A WSL distro as a host** (ADR 0081): the Linux engine unchanged
  inside, the Windows window its client, as VS Code Remote-WSL and Zed
  do. A `wsl` route beside `ssh`. A relay started with `wsl.exe` runs as
  the Linux user, so the owner socket's check holds inside the distro.
- **C. A WSL distro as an environment** (ADR 0084), with the engine on
  Windows. It breaks decision 3 (same paths), decision 6 (the door's
  socket), moves CLI lookup into the port, and with default interop and
  automount it is no wall.

Lean: A, plus B through ADR 0081; not C.

Task Scheduler gotchas ([TaskSettings](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings)):
a task stops after 72 h by default (`ExecutionTimeLimit=PT0S`);
`DisallowStartIfOnBatteries` and `StopIfGoingOnBatteries` must be false;
the default priority (7) is below normal; whether `RestartOnFailure`
covers a crash after start needs a spike; a task runs a console program
in a visible console window.

- **The session's environment:** Windows gives PATH from the registry.
  The OpenSSH agent on Windows is a named pipe,
  `\\.\pipe\openssh-ssh-agent`, so nothing like `SSH_AUTH_SOCK` needs
  carrying.
- **`KillMode=mixed` / `OOMPolicy=continue`:** a Job Object per Harness
  and terminal tree, with `KILL_ON_JOB_CLOSE`; a clean stop closes the
  adapter's stdin, waits, then ends the Job Object; if the engine dies,
  its handles close and the children die with it.
- **Own copy:** Windows can rename a running `.exe` but not delete it.
  A copy the app makes carries no Mark of the Web.
- **Living past the window:** (a) the macOS model, Electron stays with a
  tray icon; (b) the Linux model, Electron exits and the engine sends
  notifications. (a) avoids an AppUserModelID and COM activator in a
  second exe.
- **Logout:** `CTRL_LOGOFF_EVENT` is "received only by services"
  ([HandlerRoutine](https://learn.microsoft.com/en-us/windows/console/handlerroutine)).
  The engine opens a hidden top-level window (a message-only window gets
  no broadcasts) and handles `WM_QUERYENDSESSION`/`WM_ENDSESSION`, within
  about 5 s (`SPI_GETWAITTOKILLTIMEOUT`).

### 5.3 The owner channel

Today a client proves it is the owner with a secret from `engine.json`
over TCP loopback (`places.rs:23-24`, `:37-42`; `client.rs:112-128`;
`api.rs:164-180`). On Windows that file is protected by the inherited
access list of `%LOCALAPPDATA%`, and any process of the user can read
it, as on Linux today.

The named pipe design, for when a fence makes it worth having (the ADR
defers it to the MXC spike):

- **Name:** pipe names are machine-wide, so the name carries a hash of
  the user's SID and the folder: `\\.\pipe\banda-<folder>-<sid8>-owner`.
- **Server:** `first_pipe_instance(true)`, `reject_remote_clients(true)`,
  and a DACL `D:P(A;;GA;;;<PersonSID>)(A;;GA;;;SY)` with the default
  Medium no-write-up label. Nothing for Everyone or ALL APPLICATION
  PACKAGES. tokio's `named_pipe::ServerOptions` has the first two; the
  access list needs a raw call.
- **Client check:** `ImpersonateNamedPipeClient`, `OpenThreadToken`, then
  `TokenUser`, `TokenIsAppContainer`, `IsTokenRestricted` and
  `TokenIntegrityLevel`. Reading the connection's token avoids the PID
  reuse race; [`GetNamedPipeClientProcessId`](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getnamedpipeclientprocessid)
  is only for the log.
- **Rule:** the Person's SID, no AppContainer, not restricted, integrity
  Medium or higher means owner. The same SID with a fenced token is an
  Agent.
- **The client checks the server:** its token's user is the Person, and
  its image is under `<data>\engine\`.
- **AF_UNIX on Windows** has no ancillary data
  ([MS blog](https://devblogs.microsoft.com/commandline/af_unix-comes-to-windows/));
  `SIO_AF_UNIX_GETPEERPID` gives a PID only.
- **On Windows the peer-user check alone tells nothing apart.** An
  unfenced Agent runs as the Person's SID with a normal token. The check
  works only once the fence changes the Agent's token.

## 6. The critique of the first draft

The critic read the first draft of ADR 0090 against the code and the
dependencies' sources. The ADR as proposed answers each point; where it
does not, the point is an open question there.

### 6.1 Blockers

- **B1. Decision 3 could not hold for terminals.** The draft had every
  program "start suspended, put in its Job Object, then resume", and
  terminals on portable-pty. portable-pty 0.9.0 `src/win/psuedocon.rs`
  calls `CreateProcessW` with only `EXTENDED_STARTUPINFO_PRESENT |
  CREATE_UNICODE_ENVIRONMENT`: no `CREATE_SUSPENDED`, no job list, and
  the flags cannot be changed. Fix: Banda's own ConPTY start with
  `PROC_THREAD_ATTRIBUTE_JOB_LIST` (Windows 10 1607+). _ADR: decision 4._
- **B2. A terminal with no Pane hangs.** portable-pty hard-codes
  `PSEUDOCONSOLE_INHERIT_CURSOR | RESIZE_QUIRK | WIN32_INPUT_MODE`. With
  `INHERIT_CURSOR`, ConPTY sends `ESC[6n` and waits; Microsoft's
  `CreatePseudoConsole` docs say the caller must answer asynchronously or
  it may hang. The engine has no VT parser, and a replay has its answers
  off (`apps/terminal/engine/src/history.rs:1-6`). _ADR: no flags,
  decision 4._
- **B3. "The ConPTY that ships with Windows" was false.** portable-pty
  loads a bare `conpty.dll` first and falls back to kernel32. The default
  DLL search order is the app folder, system folders, the current
  folder, then PATH ([DLL search order](https://learn.microsoft.com/en-us/windows/win32/dlls/dynamic-link-library-search-order)).
  _ADR: kernel32's `CreatePseudoConsole` and `SetDefaultDllDirectories`,
  decision 4._
- **B4. The hidden console and Ctrl+Break contradicted each other.**
  `CREATE_NO_WINDOW` gives a child a new hidden console;
  `GenerateConsoleCtrlEvent` reaches only processes that share the
  caller's console. Electron, which runs the adapters until `node.exe`,
  has no console. `client/desktop/src/child.ts:29-44` starts the engine
  with no `windowsHide`, `stderr: "inherit"` and `killSignal: "SIGTERM"`,
  which Node turns into TerminateProcess. _ADR: only the engine's start
  is hidden, programs inherit its console, no Ctrl+Break in v1, the
  window closes stdin; decisions 3 and 5._
- **B5. Adapters on Electron-as-Node from step 5 to step 9.** codex-acp
  2.5.0 starts `codex.exe` with `cross-spawn(codexPath, args, { env })`,
  no `windowsHide` (`dist/index.js:28101`), so each Codex start opens a
  console window under a console-less host. Fix: `node.exe` at step 5,
  in a subfolder so `first_on_path` (`apps/agents/engine/src/lib.rs:153-169`)
  does not put it on Agents' PATH; `windowsHide` in Banda's codex-acp
  patch (`pnpm-workspace.yaml:32`); cost the pinned download, the
  license, and re-shipping on Node security releases. _ADR: decision 5,
  step 5._
- **B6. `CREATE_BREAKAWAY_FROM_JOB` fails inside Banda's own Jobs.**
  process-wrap 10.0.1's `JobObject` sets `KILL_ON_JOB_CLOSE` only;
  libuv's comment says the flag "makes the CreateProcess call fail if
  we're under job control that doesn't allow breakaway". Banda cannot
  allow breakaway: Node, Electron and Bun put their children in a libuv
  job with `SILENT_BREAKAWAY_OK`, so tool processes could leave Banda's
  Job Object (`JOBOBJECT_BASIC_LIMIT_INFORMATION` docs). ADR 0086 decision
  7 had no Windows form. _ADR: a client inside Banda's Job Objects never
  starts an engine; an Agent's Banda Local test run ends with its Job
  Object; decision 5._
- **B7. The NSIS installer kills the other channel.**
  `allowOnlyOneInstallerInstance.nsh:66`, `:94` match
  `$_.Path.StartsWith('$INSTDIR', 'CurrentCultureIgnoreCase')` and run
  `Stop-Process`; with no trailing `\`, Banda's install matches Banda
  Dev's folder. The fallback at `:97`, `:99` is `taskkill /IM`. Today's
  update stops the engine first (`client/desktop/src/main.ts:326-335`).
  _ADR: a `customCheckAppRunning` macro on `$INSTDIR\` with no name
  fallback; until step 10 an update stops the engine; decision 8._
